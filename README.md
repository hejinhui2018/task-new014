# 主题发布台（Theme Release Console）

品牌团队的主题发布前检查工具：在改动主色、文字色或按钮状态色之前，提前发现哪些页面会失去对比度、哪些令牌会继承到错误的颜色。

技术栈：**React 18 + TypeScript + Vite**，数据只保存在浏览器 `localStorage`，无任何后端。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器（默认 http://localhost:5173）
npm test           # 运行全部测试（Vitest，32 个用例）
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm run preview    # 预览生产构建
```

## 令牌模型

两层令牌构成一张有向依赖图（`src/theme/types.ts`）：

- **基础令牌**：字面值颜色，如 `blue.600 = #2563eb`；
- **语义令牌**：三种取值——
  - `color`：字面值颜色；
  - `ref`：引用另一个令牌，如 `action.primary.bg → blue.600`；
  - `transform`：对引用做变换，`lighten` / `darken`（HSL 明度）或 `mix(a, b, t)`（线性混合）。
    按钮的 hover / disabled 状态色就是这样推导的：
    `action.primary.bg.hover = darken(action.primary.bg, 8%)`。

修改一个基础令牌后，解析器（`src/theme/graph.ts` 的 `resolveAll`）沿依赖图重算，
所有依赖它的语义令牌、两个主题、hover/disabled 状态色都会即时更新。

**深色主题 = 覆盖表**：`doc.dark.semantic` 只存放与浅色不同的令牌，未覆盖的令牌
（包括变换公式）自动继承浅色定义并解析深色下的引用。在深色模式下编辑令牌即创建覆盖，
可一键「移除深色覆盖」恢复继承。

**不绕过依赖图**：预览组件的样式表 `src/styles/preview.css` 中只允许出现
`var(--t-*)` 令牌变量，变量值由 `resolveAll` 注入 `.preview-scope`。
`src/theme/preview-css.test.ts` 会拦截任何硬编码的 hex / rgb() / 颜色关键字。
解析失败的令牌渲染成品红斜纹（`#ff00ff`），让问题一眼可见。

## 内置场景

- **默认主题**：健康的品牌主题，浅色 / 深色下 15 个对比度检查对全部通过；
- **高对比度 · 问题示例**：故意包含三类问题，用于演示诊断能力——
  1. 对比度不足（浅灰文字、白字浅按钮、琥珀色互相叠放等，深色下另有深灰文字）；
  2. 循环依赖（`info.bg ↔ info.text` 互相引用）；
  3. 缺失引用（`field.border → gray.250` 不存在）。

顶栏「恢复示例」可把任一内置场景载入为**一条可撤销的命令**（载入场景刻意绕过
单令牌校验，模拟一次糟糕的导入，问题由诊断面板暴露）。

## 功能清单

- **编辑令牌**：基础令牌行内直接改色；语义令牌在详情卡中切换 引用 / 颜色 / 变换；
- **切换主题**：顶栏浅色 / 深色切换，诊断与预览同步切换；
- **来源链**：选中任一令牌，详情卡展示它一路追溯到基础令牌的完整链路，
  以及「被哪些令牌引用、共影响多少个令牌」；
- **循环拒绝**：编辑时若新引用会形成环（含自引用），命令被拒绝并在顶部提示，
  文档保持不变；
- **撤销 / 重做**：全部编辑都是可逆命令（上限 100 步），快捷键
  `Ctrl/⌘+Z`、`Ctrl/⌘+Shift+Z`（或 `Ctrl+Y`）；
- **状态模拟**：预览工具栏可强制所有组件进入 悬停 / 禁用 状态（真实 `:hover`
  与 `:disabled` 同样生效，由同一组令牌驱动）；
- **对比度诊断**：每个检查对展示实际渲染的文本样例、前景 / 背景色值、字号、
  比值与 WCAG 等级（AAA / AA / 仅大字 AA / 未通过），未通过优先排序，
  禁用态按 WCAG 惯例标为「参考」不计入问题数；
- **本地持久化**：文档、当前主题、场景 id 自动存入 `localStorage`
  （键 `theme-release-console:v1`），刷新后恢复；撤销历史不持久化。

## 测试

`npm test` 运行 5 个测试文件、32 个用例，覆盖需求要求的五个方面及更多：

| 测试文件 | 覆盖点 |
| --- | --- |
| `src/theme/graph.test.ts` | **依赖传播**（改基础令牌 → 引用链 / 变换链全部更新）、来源链、**循环检测**、缺失引用诊断 |
| `src/theme/store.test.ts` | **循环拒绝**（reducer 拒绝成环命令）、**主题覆盖**（覆盖 / 移除覆盖 / 继承）、**状态色**（hover/disabled 随基础色与主题更新）、**撤销重做**（含恢复场景、重做栈清空） |
| `src/theme/color.test.ts` | hex 解析、HSL 变换、WCAG 亮度 / 对比度 / 评级阈值 |
| `src/theme/preview-css.test.ts` | 守护测试：预览样式不得硬编码颜色，必须经由 `var(--t-*)` |
| `src/App.test.tsx` | 冒烟测试：整棵组件树渲染不崩溃，三栏与令牌变量就位 |

## 目录结构

```
src/
  theme/            # 纯逻辑，无 React 依赖，全部可单测
    types.ts        #   令牌与文档模型
    color.ts        #   颜色解析 / 变换 / WCAG 对比度
    graph.ts        #   依赖图：解析、循环检测、来源链、诊断、CSS 变量生成
    pairs.ts        #   对比度检查对定义与求值
    presets.ts      #   内置场景（默认主题 / 问题示例）
    store.ts        #   命令、撤销重做、编辑校验（循环拒绝）、localStorage
  components/       # 三栏 UI：TokenPanel / TokenEditor / PreviewPanel / DiagnosticsPanel / TopBar
  styles/
    app.css         # 工具外壳样式（与令牌系统无关）
    preview.css     # 预览组件样式（颜色只允许 var(--t-*)）
```
